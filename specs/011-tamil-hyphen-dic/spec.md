## User Scenarios & Testing *(mandatory)*

### User Story 1 - Export Phonotactically Verified TeX/Hunspell Pattern Dictionary (Priority: P1) 🎯 MVP

As an open-source font developer, desktop publishing user, or Linux distribution packager, I want a tool to generate a standards-compliant, phonotactically verified Frank Liang / Hunspell hyphenation dictionary (`hyph_ta_IN.dic`) directly from the verified `tamil-hyphen` linguistic engine, so that word processors and layout engines (LibreOffice, Adobe InDesign, Scribus, XeTeX/LuaTeX) can break Tamil words at grammatically sound syllable boundaries without human intervention.

**Why this priority**: Word processors rely on TeX/Hunspell Liang pattern tables (`.dic` files) rather than custom runtime binaries. Generating an accurate, bug-free `hyph_ta_IN.dic` directly from our verified Rust engine solves the long-standing justification and hyphenation defects in LibreOffice, InDesign, and Scribus immediately.

**Independent Test**: Can be tested independently by running `tamil-toolkit hyphen export-dic --output hyph_ta_IN.dic` and verifying that the generated dictionary passes pattern syntax linting, declares `LEFTHYPHENMIN 2` and `RIGHTHYPHENMIN 2`, prohibits breaking Grantha ligatures (`க்ஷ`, `ஸ்ரீ`), and binds all pure consonants (*Mei*) and Aytham (*ஃ*) to their preceding syllable.

**Acceptance Scenarios**:
1. **Given** the `tamil-hyphen` phonotactic rule engine, **When** invoking pattern generation, **Then** the output dictionary strictly enforces `LEFTHYPHENMIN 2` and `RIGHTHYPHENMIN 2`, preventing single-letter orphan splits (e.g. `அ-ம்மா` or `பா-ல்`).
2. **Given** words containing pure consonants (*Mei*, `\u{0BCD}`) or Aytham (`\u{0B83}`), **When** applying Liang patterns, **Then** odd/even pattern weights ensure a break is never placed before a virama, after an isolated consonant, or before an Aytham character.
3. **Given** atomic Grantha ligatures (`\u{0B95}\u{0BCD}\u{0BB7}` *Ksha*, `\u{0BB8}\u{0BCD}\u{0BB0}\u{0BC0}` / `\u{0BB6}\u{0BCD}\u{0BB0}\u{0BC0}` *Shri*), **When** generating hyphenation patterns, **Then** patterns explicitly inhibit breaks inside the ligature sequence (`2க்ஷ2`, `2ஸ்ரீ2`).
4. **Given** a multi-consonant coda cluster (e.g., `\u{0BB0}\u{0BCD}\u{0BAA}\u{0BCD}` in `துர்ப்பிரயோகம்`), **When** applying pattern weights, **Then** the break occurs exclusively after the entire coda cluster and never between the internal consonants of the cluster.

### Edge Cases

- **One-letter prefixes & suffixes (`அ-ம்மா`, `பா-ல்`)**:
  - In English, `LEFTHYPHENMIN 2` prevents `a-bout`. In Tamil, breaking after initial independent vowel `அ` or before trailing single letter leaves an orphaned letter that looks aesthetically and grammatically broken. `LEFTHYPHENMIN 2` and `RIGHTHYPHENMIN 2` (measured in Unicode scalar / syllable clusters) MUST be enforced so words with fewer than 4 letters are never broken.
- **Grantha and Conjunct Ligatures (`க்ஷ`, `ஸ்ரீ`)**:
  - The sequence `க்` (`\u0B95\u0BCD`) followed by `ஷ` (`\u0BB7`) forms the single orthographic ligature *Ksha*. In legacy SMC, `2\u0B95\u0BCD1` allows a break directly after the virama, splitting `க்-ஷ`. The new patterns MUST insert blocking weights (`2க்ஷ2`, `2க்ஷ`, `க்ஷ2`) to prevent splitting within conjuncts.
- **Consecutive Consonant Clusters (Geminates & Multi-Mei)**:
  - Sequences like `த்த்`, `ர்ப்ப்`, `ற்க்` contain multiple pure consonants. In legacy dictionaries, individual `2C\u0BCD1` rules allowed breaking after the first consonant (e.g. `துர்-ப்பயன்பாடு`). All consonants in a syllable coda belong to the preceding nucleus; the break MUST occur only after the final consonant with virama in the sequence.
- **Aytham (`ஃ`, `\u0B83`)**:
  - Aytham is grammatically an *Eduthu-coda* or dependent letter. A line segment or hyphenated segment MUST NEVER start with `ஃ`. Patterns MUST inhibit breaks immediately before `ஃ` (`2ஃ`).
- **Combining Marks at Word Boundaries**:
  - Combining marks (virama `\u{0BCD}`, vowel signs `\u{0BBE}`-`\u{0BCC}`) must never appear at the beginning of a pattern without their base consonant, preventing dangling combining marks if an engine evaluates substring slices.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST provide an algorithmic pattern generation engine that programmatically compiles Tamil phonotactic rules and coda-binding invariants from `tamil-hyphen` into standard Frank Liang / TeX hyphenation patterns (compatible with Hunspell / Hyphen / `libhyphen`) without requiring external statistical training tools (`patgen`).
- **FR-002**: System MUST generate dictionary headers with explicit parameters:
  - `UTF-8` character encoding declaration.
  - `LEFTHYPHENMIN 2` and `RIGHTHYPHENMIN 2`.
  - Upstream-compatible permissive open-source licensing header (MIT / LGPL / GPL tri-license).
- **FR-003**: System MUST generate pattern rules guaranteeing:
  - No breaks before any pure consonant + virama (`2C\u0BCD`).
  - No breaks after a pure consonant unless it is the final consonant of a complete coda cluster followed by a valid onset.
  - Strict preservation of Grantha ligatures (`க்ஷ`, `ஸ்ரீ`) with zero internal break opportunities.
  - No breaks immediately before or after Zero-Width Joiner (ZWJ, `\u200D`).
  - Aytham (`\u0B83`) strictly attached to its preceding vowel/consonant nucleus.
- **FR-004**: System MUST expose a command-line interface `tamil-toolkit hyphen export-dic`:
  - `--output <PATH>`: Destination path for the `.dic` file (defaults to `hyph_ta_IN.dic`).
  - `--lefthyphenmin <N>`: Configurable left margin (default `2`).
  - `--righthyphenmin <N>`: Configurable right margin (default `2`).
- **FR-005**: System MUST provide an automated verification test suite in Rust and Python that loads `hyph_ta_IN.dic`, evaluates every test case in `tests/golden/hyphen_syllable.jsonl`, and asserts:
  - 100% agreement on permissible syllable break boundaries.
  - Zero line segments starting with an orphaned virama, combining vowel sign, pure consonant, or Aytham.
- **FR-006**: System MUST provide an automated diff/comparison tool that benchmarks the generated `hyph_ta_IN.dic` against the legacy 2018 SMC `hyph_ta_IN.dic`, reporting:
  - Number of words tested.
  - Number of illegal breaks permitted by legacy vs new patterns.
  - Concrete examples of fixed words (including `அகிலத்திரட்டு`, `துர்ப்பிரயோகம்`, `பல்கலைக்கழகம்`, `தக்ஷிணம்`, `ஸ்ரீலங்கா`).
- **FR-007**: System MUST provide an automated packaging script that bundles the generated dictionary into a standard LibreOffice extension:
  - `tamil-hyphenation.oxt` (ZIP format).
  - `META-INF/manifest.xml` defining package contents.
  - `dictionaries.xcu` binding `hyph_ta_IN.dic` to all Tamil locales: `ta-IN`, `ta-LK`, `ta-SG`, `ta-MY`, and generic `ta`.
  - `description.xml` with extension metadata, bilingual display names (English and Tamil), versioning, and publisher information.
- **FR-008**: System MUST provide clear, step-by-step user documentation (`docs/integrations/libreoffice.md`, `indesign.md`, `scribus.md`) detailing installation, activation, and verification in each respective application.
- **FR-009**: System MUST generate an upstream contribution bundle in `dist/upstream-smc/`:
  - `ta_IN/hyph_ta_IN.dic` ready for replacement in `github.com/smc/hyphenation`.
  - `UPSTREAM_PR.md` containing PR title, technical justification, phonotactic rationale, test methodology, and comparative benchmark results.
- **FR-010**: Playground web UI MUST provide an "Integrations & Downloads" card within the Syllabic Hyphenator tool offering direct one-click browser downloads for `tamil-hyphenation.oxt` and `hyph_ta_IN.dic`, along with an interactive 3-step installation guide for LibreOffice and InDesign users.

### Key Entities

- **LiangPattern**: A string pattern consisting of characters interleaved with numeric weights (`0`-`9`), where odd numbers represent valid break points and even numbers inhibit breaks, with higher numbers overriding lower numbers.
- **HyphenationDictionary (`.dic`)**: A plain text file encoded in UTF-8 containing the header parameters (`LEFTHYPHENMIN`, `RIGHTHYPHENMIN`), license notice, and the sorted list of Liang patterns.
- **LibreOfficeExtension (`.oxt`)**: A ZIP archive containing configuration XMLs (`dictionaries.xcu`, `description.xml`, `manifest.xml`) and the dictionary file, recognized by LibreOffice Extension Manager.
- **UpstreamContributionKit**: A documentation and artifact package formatted specifically for external maintainer review on GitHub/GitLab.

## Long-Term Integration Roadmap: Consumer Word Processors

While open-standard desktop publishing tools (LibreOffice, InDesign, Scribus) consume standard Frank Liang `.dic` tables, consumer cloud and desktop word processors (**Microsoft Word** and **Google Docs**) do not support drop-in Hunspell files or native Indic syllabic breaking.

To solve this universally without altering letter-spacing or kerning on the same line, the project specifies a phased integration roadmap powered by the **Unicode Soft Hyphen (`\u{00AD}`)**:

See full technical architecture in [docs/integrations/word-googledocs-roadmap.md](file:///C:/Users/abish/Documents/dev/tamil-toolkit/docs/integrations/word-googledocs-roadmap.md) and [ROADMAP.md](file:///C:/Users/abish/Documents/dev/tamil-toolkit/ROADMAP.md).

### Future Phased Requirements

- **Phase 1: Web & Manual Copy (Completed & Live)**: The Playground provides instant Unicode Soft-Hyphen clipboard export. Pasting into Word with Justify (`Ctrl + J`) dynamically breaks lines at margin boundaries while keeping same-line tracking completely untouched.
- **Phase 2: Headless DOCX Batch CLI Processor (Target: v0.2.0)**:
  - Subcommand: `tamil-toolkit hyphen process-docx --input doc.docx --output out.docx`
  - OpenXML DOM traversal parsing Tamil paragraph text runs and inserting soft hyphens while strictly preserving styles, headings, tables, and hyperlinks.
- **Phase 3: Microsoft Word Web Add-in (`Office.js`) (Target: v0.3.0)**:
  - Cross-platform Taskpane Add-in running locally inside Word on Windows, macOS, and Web.
  - Powered by client-side WebAssembly (`tamil-toolkit-wasm`) for 100% private, offline in-document hyphenation.
- **Phase 4: Google Workspace Docs Add-on (Target: v0.4.0)**:
  - Container-bound / Google Workspace Marketplace add-on traversing Google Docs elements via Apps Script.
- **Phase 5: Operating System Linguistic Providers (Future Exploration)**:
  - Windows Linguistic Services (`ISpellCheckProviderFactory`) and macOS `NSSpellServer` CoreText hyphenation dictionaries.
